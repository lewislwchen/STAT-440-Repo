Transforming Data: Combining

  • When you need to work with multiple datasets of the same subject matter

  • Can increase overall amount of information

  • Could mean concatenating, binding, or joining

  • Concatenating is the act of combining objects or strings together

  • Typically concatenate with c(), paste(), or glue() (within the glue package)

c(1, 3:5, 'animals')

c(iris, 1, 3:5, 'animals')

paste(1, 3:5, 'animals')

glue::glue('{1} {3:5} animals')

data01 |> mutate(new_string_column = glue::glue('What a piece of {column_name01}!')

  • Binding is the act of combining two or more objects by stacking

  • Binding rows makes sense when there are two or more datasets with exact same column information and number of columns

  • Binding columns makes sense when there are two or more datasets with exact same rows information and number of rows

    • In the tidyverse package, bind_rows(data01, data02) stacks objects on top of each other, while bind_cols(data01, data02) stacks objects side by side

    • In base R, rbind(data01, data02) stacks objects on top of each other, while cbind(data01, data02) stacks objects side by side

  • Recall mutating a row is the same as a single-row bind with add_row() function within the tidyverse package

  • Joining usually implies combining two or more objects with different columns of information into one single object.

  • Joining works best when each of the different data objects to have at least one column in common with a unique identifying information, such as an ID variable or geographic location. There are at least 3 situations that can occur when merging objects.

  • Joining Scenario 1: observations in the two (or more) separate objects’ values do not match each other.

  • If we intend on keeping rows for which there are only matches between both data1 and data2 then we likely want an inner join: inner_join(data1, data2, by = column_name) in tidyverse package

  • If we intend on keeping rows for which observations in data1 are preserved and keeps matches from data2, then we likely want a left join: left_join(data1, data2, by = column_name) in tidyverse package

  • If we intend on keeping rows for which observations in data1 and data2 are preserved and keeps matches and non-matches from both, then we likely want a full join: full_join(data1, data2, by = column_name) in tidyverse package

  • If the identifying columns’ names are not the same, but the information in both are the same, then we can specify the two column names in the by = argument: inner_join(data1, data2, by = join_by(column_name01 == column_name02)) in tidyverse package

Review: Relational Database Terminology

Data information
Database a set of related information, such as Contacts, Spotify, iCard, etc.; often written as DB, dB, or db
Query a question, task, or request written to find data
Entity data of specific interest, such as customers, parts, geographic locations, etc.
Column individual piece of data stored in a table
Row set of columns that together completely describe an entity; a record or observation
Table set of rows, held either in memory (nonpersistent) or on permanent storage (persistent)
Result Set the resulting SQL query; a nonpersistent table
Primary Key one or more columns that can be used as a unique identifier for each row in current table; ideally every table has a primary key
Foreign Key one or more columns that can be used together to identify a single row in another table; not a primary key in current table

SQL Query Order of Evaluation

  • After database connection is established and before the connection is closed, the database server checks the following:

    • Is the user allowed to write a SQL query?
    • Is the user allowed to access the data?
    • Is the user’s query valid?

  • If yes to all 3 questions, then the query optimizer determines the execution plan for the best way to execute the query

  • The order of evaluation of typical clauses and components is as follows:

  1. FROM
  2. WHERE
  3. GROUP BY
  4. HAVING
  5. SELECT
  6. DISTINCT
  7. ORDER BY
  8. LIMIT and OFFSET

  • UNION removes duplicate rows, while UNION ALL keeps all rows including duplicates.

  • If we intend on keeping rows for which there are only matches between both data1 and data2 then we likely want an inner join:

SELECT *

  • If we intend on keeping rows for which observations in data1 are preserved and keeps matches from data2, then we likely want a left join:

SELECT *

SELECT *
FROM data1 FULL JOIN data2 ON data1.column_name = data2.column_name;

Transforming Data in SQL: Filtering Rows and Dropping Missing Values with WHERE

  • Because the WHERE clause is evaluated after the FROM clause, any actions taken during the WHERE cannot be referenced in the previously-evaluated clause

  • In SQL, limit row output based on conditions using WHERE

  • There are helpful operators and functions for filtering rows in SQL, such as =, <>, >, <, >=, <=, AND, OR, NOT, LIKE, IN, BETWEEN, and ( ) for grouping conditions

SELECT *
FROM data_name
WHERE (column_name01 = condition01) AND (column_name02 <> condition02);

  • For filtering with LIKE, the % wildcard is used to match any number of characters, while the _ wildcard is used to match a single character

SELECT *
FROM data_name
WHERE column_name01 LIKE '%';

  • To filter with IN, we can specify a list of values to match

SELECT *
FROM data_name
WHERE column_name01 IN (condition_values);

  • In SQL, missing values are coded as NULL. Removing them is done with the IS NULL or IS NOT NULL keywords in the WHERE statement.

SELECT *
FROM data_name
WHERE column_name IS NOT NULL;

Transforming Data in SQL: Group Processing with GROUP BY

  • Because the GROUP BY clause is evaluated after the FROM and WHERE clauses, any actions taken during the GROUP BY cannot be referenced in the previously-evaluated clauses

  • In SQL, the GROUP BY clause allows us to do data processing separately for each specified combination of groups in a table

    • does not explicitly change the table
    • evaluated before mutating or summarizing with SELECT clause

SELECT column_name01, column_name02, function_name01(column_name03) AS new_column_name01
FROM data_name
GROUP BY column_name01, column_name02;

Transforming Data in SQL: Filtering Groups with HAVING

  • Because the HAVING clause is evaluated after the FROM, WHERE, and GROUP BY clauses, any actions taken during the HAVING cannot be referenced in the previously-evaluated clauses

  • In SQL, after grouping data with GROUP BY, we can limit grouped data output based on conditions using HAVING

  • There are helpful operators and functions for filtering groups including summary (or aggregate) functions, such as SUM(), COUNT(), AVG(), as well as comparison operators such as =, <>, >, <, >=, <=, AND, OR, NOT

SELECT *
FROM data_name
GROUP BY column_name01
HAVING summary_function_name01(column_name02) > condition01;

Transforming Data in SQL: Organizing, Renaming Columns, Removing Duplicates, and Mutating Columns with SELECT

  • Because the SELECT clause is evaluated after the FROM, WHERE, GROUP BY, and HAVING clauses, any actions taken during the SELECT cannot be referenced in the previously-evaluated clauses

  • In SQL, we may select columns by writing their name after the SELECT clause

SELECT column_name01, column_name02, column_name03
FROM data_name;

  • We can select all columns with SELECT *

SELECT *
FROM data_name;

  • We can rename columns with AS in the SELECT clause
    • This does not change the column name in the source data, but only in the resulting table
    • Below, new_column_name01 and new_column_name02 cannot be used or referenced in the WHERE, GROUP BY, or HAVING clauses because the column names are evaluated after those clauses

SELECT column_name01 AS new_column_name01, column_name02 AS new_column_name02
FROM data_name;

  • If we want to remove duplicate rows, then we can use the DISTINCT keyword in the SELECT clause
    • This does take up computational resources

SELECT DISTINCT column_name01, column_name02
FROM data_name;

  • We mutate new columns in the SELECT clause as long as the new columns are created with vectorized operations and functions. If the new column is created with a summary or aggregate operation or function, then we summarized the data, not mutated.

  • Many vectorized functions and operators exist in SQL

    • arithmetic operators: +, -, *, /, MOD(), POWER()
    • logical operators: >, <, >=, <=, =, and <>
    • mathematics functions: EXP(), LOG(), SQRT(), ABS(), RAND(), and ROUND()
    • string manipulation functions: CONCAT(), SUBSTRING(), UPPER(), and LOWER()
    • conditional functions: IF(), and CASE WHEN THEN ELSE END

  • Several summary or aggregate functions exist in SQL, such as SUM(), COUNT(), AVG(), MIN(), and MAX()

  • Multiplying by 1.0 is a common trick to convert integers to decimals in SQL

SELECT function_name01(column_name01) AS new_column_name01, function_name02(column_name02) AS new_column_name02
FROM data_name;

SELECT column_name01, IF(column_name02 = original_value01, new_value01_if_true, new_value02_if_false) AS new_column_name01
FROM data_name;

SELECT column_name01, CASE WHEN column_name02 = original_value01 THEN new_value01 WHEN column_name02 = original_value02 THEN new_value02 ELSE new_value03 END AS new_column_name01
FROM data_name;

  • We can mutate literal values in the SELECT clause, such as numbers, strings, and dates

SELECT column_name01, 'literal_string' AS new_column_name01, 1 AS new_column_name02, '2024-06-01' AS new_column_name03
FROM data_name;

Transforming Data in SQL: Arranging or Sorting

  • In SQL, we can arrange or sort the resulting table based on specified column(s) in ascending or descending order with ORDER BY clause
    • The default ordering is ascending. If we want descending order, then we use the DESC keyword after the field name.

SELECT * FROM data_name
ORDER BY column_name01 ASC, column_name02 DESC;

Transforming Data in SQL: Slicing

  • In SQL, limit row output based on row index or position using LIMIT and its relative OFFSET

SELECT *
FROM data_name
LIMIT number_of_rows OFFSET number_of_rows_to_skip;

  • If wanting to mimic the tidyverse package’s slice_sample() function, then we can use ORDER BY RAND() to randomize the row order and then limit the number of rows returned with LIMIT
    • If the data has many rows, then RAND() may take a while to process

SELECT *
FROM data_name
ORDER BY RAND()
LIMIT number_of_rows;
