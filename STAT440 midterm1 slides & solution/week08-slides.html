Transforming Data in SQL: Counting Values COUNT

  • We can count the rows using COUNT(*), which includes NULL and duplicate values

  • We can count the values of a specific column using COUNT(column_name01) which includes duplicate values

  • We can count the non-duplicate and non-NULL values of a specific column using COUNT(DISTINCT column_name01)

Subqueries in SQL

  • Query structure is the same for subqueries but enclosed in parentheses

(SELECT column_name01, column_name02
FROM table_name01
WHERE row_condition01
GROUP BY column_name01
HAVING group_condition01
ORDER BY column_name01
LIMIT number_of_rows OFFSET number_of_rows_to_skip);

  • Some subqueries can be executed independently, which means they are non-correlated

  • Some subqueries will be executed for row that might be included in the resulting set, which means they are correlated

  • When using a subquery in the FROM clause, it requires an alias using AS because it represents a derived table

String Manipulation in SQL: Concatenating Strings via CONCAT()

  • We can paste strings together with CONCAT(string01, "separator_value01", string02) much like paste() in base R

    • each string01 and string02 can be a literal string or a column in the data table; for example, last_name and first_name in the ccso_jail data
    • "separator_value01" is any character for separating the strings; for example, “,” as comma separator between last_name and first_name

String Manipulation in SQL: Collapsing Strings via GROUP_CONCAT()

  • We can collapse strings to a single string for each group with GROUP_CONCAT(DISTINCT column_name_with_multiple_strings ORDER BY column_name_if_string_order_matters separator "separator_value01") much like paste(..., collapse = "separator_value01")

    • GROUP_CONCAT() is typically used when there is a GROUP BY in the query; for example, there may be multiple crimes for each jacket_number in the ccso_jail data

    • DISTINCT is optional and removes duplicate string values in the column_name prior to collapsing them; for example, one jacket_number may have the same crime at a single booking

    • column_name_with_multiple_strings is ideally a column that has the strings for which you want to collapse; for example, crime

    • ORDER BY is optional and sorts the strings to be collapsed; for example, we may want to alphabetize the crimes or order them by final answer code

    • separator "separator_value" is optional and sets the separator character between the strings for collapsing; if omitted, the separator defaults to comma;

Transforming Data in SQL: Summarizing with Analytic Functions

  • We have performed queries including summarized or aggregate functions and the resulting set may be summarized in the sense that the resulting rows correspond to the groups set in the query

    • Several summary or aggregate functions exist in SQL, such as SUM(), COUNT(), AVG(), MIN(), MAX()

  • Analytic functions utilize the notion of “data windows” and “frames” in SQL

  • “Data windows” are the grouped rows which allow the data to be partitioned per group so that an analytic function can be applied

  • To create a window for the purpose of summarizing, we use SUMMARY_FUNCTION01(column_name01) OVER(PARITION BY column_name_containing_groups) within the SELECT clause

    • OVER() allows the summary function to be applied over all rows because there is no specified window or group of rows; for example in the ccso_jail data, we could compute the average number of crimes across all values of jacket_number using AVG(COUNT(crime)) OVER ()

    • PARTITION BY is optional and sets the groups to be windowed for the summary function; for example in the ccso_jail data, we could compute the total days spent in jail among the bookings per jacket_number using SUM(SUM(DATEDIFF(released_date, booking_date))) OVER(PARTITION BY jacket_number)

    • column_name_containing_groups is a column that contains groups of rows; for example in the ccso_jail data, jacket_number column

Transforming Data in SQL: Ranking with Analytic Functions

  • There are three different ranking analytic functions that behave differently regarding ties:

  • RANK()… yields same ranking for ties and skips ranking numbers based on number of ties; e.g., 1, 2, 2, 4

  • DENSE_RANK()… yields same ranking for ties and continues ranking numbers based on number of ties; e.g., 1, 2, 2, 3

  • ROW_NUMEBR()… ranks based on row appearance and yields un-ordered ranking for ties; e.g., 1, 2, 3, 4

  • To create a window for the purpose of ranking, we use RANK() OVER(PARITION BY column_containing_groups ORDER BY column_to_be_ranked) within the SELECT clause

    • OVER(ORDER BY column_to_be_ranked) allows the ranking to be applied over the column to be ranked; for example in the ccso_jail data, after computing the total booked crimes per jacket_number, we could rank the total booked crimes using RANK() OVER(ORDER BY COUNT(crime) DESC)

    • PARTITION BY is optional but appears before ORDER BY and sets the groups to be windowed for the ranking; for example in the ccso_jail data, we could compute the total days spent in jail per booking per jacket_number and rank them using RANK() OVER(PARTITION BY jacket_number ORDER BY total_days_in_jail_per_booking DESC)
